### 4.3 不可编码字事故（重要，供其他组参考）

**事件**：`_fix10.py` 早期版本把「换字」混进了「纯字形替换」，造成 334 处语义损伤：

| 错误替换 | 处数 | 后果 | 修复 |
| --- | ---: | --- | --- |
| `獲→穫` | 78 | `獲得`→`穫得`、`捕獲`→`捕穫` | 全部回 `獲` |
| `對→対` | 62 | 与已验证 23,745 条的 `對` 形成两套写法 | 全部回 `對` |
| `讚→賛` | 44 | 换字 | 回 `讚` |
| `卻→却` | 143 | 换字 | 回 `卻` |
| `疊→畳`/`臟→臓`/`圖→図` | 13 | 换字 | 已回 |
| `勞→労`/`搖→揺` | 6 | 源字本可编码，白换 | 已回 |

**根因**：判据用了 `s.encode('cp932')` 是否抛异常，而正确判据是**排除 NEC 区**。`增`(0xED81)、`黑`(0xEEEC) 能编码但落在 NEC 区不可用；`對`(0x9B94)、`樂`、`圖`、`劍` 能编码且非 NEC，**根本不该动**。

**修复后**：全量复检 0 问题；`_fix10.py` 重写为三类分离 + `--check` 只报告模式。

## 5. 方法论沉淀

详见 `物品说明重译_方法论.md`，要点：

1. **单指针 vs 多指针**先查回填清单，别信任务书描述（物品 1 槽 / 装备 4 槽）
2. **长度比阈值法**：已完成译文长度比 P5=0.688 → `<0.70` 必然缺内容，只能重译
3. **归一化模板匹配**：去掉 `\n` 再比对，解决「同文不同断行」
4. **残片清单的反例原则**：每个字都要能举出正例（`著彈`/`著實` 是正例）
5. **不可编码字三分类**（见附录）
6. **重排引擎 3 坑**：不能硬按日文行数、标点会切出孤立行、`~C05` 缺闭合
7. **校验器只报不默改**：静默替换会长出第二套写法

### C 类 · 源字编不出但目标是「换字」 —— **禁止自动替换，人工选词**

| 源 | 建议 | 说明 |
| --- | --- | --- |
| 寬 | 廣闊 | `寬` 是 NEC；`寬廣`→`廣廣` 是错词，须改述 |
| 繫 | 相連 | `繫` 编不出；`相繫`→`相連` |
| 獲 / 穫 | **不动** | 两者都可编码，`獲得`/`收穫` 各自正确 |
| 賣 / 販 | **不动** | 两者都可编码 |
| 對 | **不动** | `對` 可编码（0x9B94），项目标准用 `對` |
| 樂 · 圖 · 劍 · 卻 · 疊 · 臟 · 讚 | **不动** | 全部可编码且非 NEC |

> **判定顺序**：① 源字 `enc_ok`（非 NEC）通过 → 不动；② NEC 或编不出且有同义日文形 → A 类；③ 编不出且无同义形 → B 类改述；④ 源字可用但「不够日式」→ **不许动**。
