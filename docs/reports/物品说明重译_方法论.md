# 物品说明重译 方法论

> 适用对象：MHF 汉化里所有「说明文本」的重译/重排。本文是物品（16,686 条）实战沉淀，防具/武器（4 槽结构）可直接复用第 1、2、3、4、6 节，第 5 节需按 4 槽改写。

---

## 0. 先搞清楚结构：单指针 vs 多指针

**这是所有判断的前提，必须先查回填清单，不要凭任务书描述。**

```python
# 回填定位_请保留.jsonl.gz → 每条记录的 description 数组长度
物品类（怪物素材/生物素材/矿石/装饰品/未分类/其他物品/食品药品/书籍票券硬币/辅助道具）
  → 全部 1 槽（单指针）
防具 5 部位 + 近战/远程武器
  → 全部 4 槽
```

**含义**：

| 结构 | `\n` 数量 | 回填方式 |
| --- | --- | --- |
| 1 槽 | 自由，不影响回填 | `backfill.set_description()` 走单指针分支，整串含 `\n` 直接写入 |
| 4 槽 | **必须 ≤ 4**，每槽一行 | 逐槽写入，超出会 `ValueError` |

所以：

- 物品：行数不是「硬约束」，但仍建议**按日文行数**产出以对齐版面；
- 装备：行数是硬约束，**行数超了会回填失败**。

---

## 1. 长度比阈值法：判断「能否重排而不重译」

**不要凭直觉判断旧译「内容是否完整」。** 用已完成译文的长度分布定阈值。

```python
ratio = len(旧译去掉\n) / len(日文去掉\n)
```

物品实测（11,872 条已完成译文的样本）：

```
均值 0.806   中位 0.815
P5  0.688  ← 完整译文的下限
P10 0.733
P25 0.778
P90 0.875
```

**判据**：

- `ratio ≥ 0.70` → 内容大体完整，**只需重排 + 潤色**（修断行、修标点、补 `~C00`）
- `ratio < 0.70` → 内容确实缺失（漏译/截断），**必须逐条重译**

物品实战：4,244 条待译中，2,107 条（50%）走重排，2,137 条走重译。**重排的 2,107 条全部一次通过校验**，省下约 8 倍工时。

> 这个阈值是「按语种对」定的。中文/日文 ≈ 0.81。若换语言对（如英→中），必须重新校准。

## 2. 归一化模板匹配：解决「同文不同断行」

同一句游戏文本在不同条目里可能因为**断行位置不同**而 `!=`，直接按 `jp_desc` 建 map 会漏。

```python
norm = {k.replace('\n', ''): v for k, v in template_table.items()}
hit = [x for x in todo if x['jp_desc'].replace('\n', '') in norm]
```

物品实战：101 条 `マイトレプーギー服の装飾品／を生産するのに必要な素材。／工房に持って行こう！` 因为换行位置与模板不同没匹配上，归一后一次命中。

**注意**：归一化后要检查**冲突**（不同原文归一到同一 key 但译文不同），有冲突就报错而不是覆盖。

## 3. 残片清单的反例原则

判断「行首是否被切断」的黑名单，**每个字都必须能举出正例**，否则清单本身就是误报源。

```python
# 错：含「著」，导致「著彈地點…」「著實難以入手…」误报
HEAD_BAD = '的了著，。、之且'

# 对：去掉 著
HEAD_BAD = '的了，。、之且'
```

同类教训：

- `裝/備` 不能进清单（`裝飾品`、`裝備後` 是正常词首）；
- 「1-2 字 + 标点」这种宽规则误报率极高（实测 26,917 → 真实 9,955）；
- 判据越宽，假阳性越多，最终会淹没真问题。

## 4. 不可机械替换字清单

有的字不可编码，但**替换成等价字会造出怪词**，必须改述而非硬替。

| 字 | 码位问题 | 错误硬替 | 正确做法 |
| --- | --- | --- | --- |
| `增` | 0xED81 落在 NEC 区 | — | 直接换 `増`（安全，1:1） |
| `值` | 0x503C 非 JIS | — | 换 `値`（安全，1:1） |
| `拼` | 非 JIS | `組合貼` | 改述：`拼貼→接合`、`拼合→接合` |
| `傢伙` | 兩字皆非 JIS | — | 改述：`那傢伙→那一位/該魔物` |
| `辦` | 非 JIS | `擧辦/舉辦` 都不行 | 改述：`舉辦→舉行` |
| `份` | 非 JIS | — | 改述：`份量→量感`、`零食份→個` |
| `烤` | 非 JIS | — | 换 `焼`（日文形，安全） |

**1:1 安全映射**（直接 replace）：`增→増 值→値 內→内 擊→撃 銳→鋭 溫→温 絕→絶 說→説 歷→歴 步→歩 勞→労 獲→穫 賣→販 對→対 寬→廣 繫→連 脫→脱 搖→揺 韌→靭 殼/殻→殼 貓→猫`

**必须改述**（不能机器替换）：`拼 傢伙 辦 份 烤 垃圾 陷阱`

## 5. 行数策略

| 结构 | 策略 |
| --- | --- |
| 物品（1 槽） | 目标 = 日文行数；**中文明显更短时允许少 1 行**（否则出现 2–3 字残行） |
| 装备（4 槽） | 固定 3 行（4 槽留 1 空），行数不得变 |

**为什么不能硬凑行数**：日文 3 行往往因为片假名怪名长；中文同义只有 6–7 字，硬拆会得到 `…的` / `。` 这种残行。

## 6. 重排引擎的 3 个实现坑

### 6.1 不能硬按日文行数装箱

```
# 错：把 15 字的一句硬塞进 3 行 → 出现「。」独占一行
# 对：k_eff = max(ceil(总宽/14), min(日文行数, round(总宽/12)))
```

按「总量 / 12」估算合理行数，再与日文行数取较小值。

### 6.2 标点会被切出孤立行

硬切超长句时若正好落在句号前，会得到 `…昆蟲` + `。`。**必须把最后一个字让给后段**：

```
错：'背部形状與顏色酷似樹葉的昆' + '蟲。'   → 尾巴只剩标点
对：'背部形状與顏色酷似樹葉的昆蟲' + '。'   ← 更糟
正解：把末字让给后段 → '…的昆' + '蟲。'
```

实现：切完后若余段全是标点，从上一段末尾挪 1 个字过来。

### 6.3 `~C05` 未闭合

旧译常见 `~C05（支給品專用）` 缺 `~C00`。重排时统计 `~C05` 与 `~C00` 数量，不足则补 `~C00`。

> 注意：`~C00` 是**关闭标记**，不是色号。统计色号要用 `~C(?!00)\d\d`。

### 6.4 孤儿修正（行首残片）

行首出现 `的/了/之/且` 时：
1. 先尝试把该字挪回上一行末尾（宽度允许时）；
2. 否则从上一行末尾拉 1 个字到本行行首，让本行不以残字开头。

## 7. 校验器清单（每批必过）

```python
1. 覆盖完整性（id 集合 == 待译集合）
2. CP932 可编码，且不落在 0xEB–0xFC（NEC 区）
3. 假名残留 = 0（排除 ・ U+30FB）
4. 行宽 ≤ 14 全角（~Cnn 与 ≪≫ 不计）
5. 行首残片 = 0（用校准过的清单）
6. 行数 ≤ 槽数（装备硬约束）
7. 色标数量与顺序 = 日文；≪≫ 配对且不跨行
8. 同一日文模板产出一致性 = 0 冲突
```

**校验不过一律退回重译/重排清单，不硬塞。** 物品 2,107 条重排全部过检，是因为不合格的 38 条被退回重译了。

## 8. 数据定义 vs 执行动作

```python
# 对：数据在模块级，import 与直接跑一致
T = {...}
if __name__ == '__main__':
    write_json(T)

# 错：生成逻辑写在 if __name__ 里，被校验器 import 时静默不执行
```

物品实战踩过：26 条参数化条目写在 `if __name__ == '__main__'` 里，校验器 `import` 时没生成，静默漏掉一批。

## 9. 占位符处理

日文原文为 `dummy / ダミー / 予定枠 / 名称仮 / 開発用 / 説明文不要` 的，**一律保留「預留」并加 note**，不编内容。物品共 944 条。

---

## 10. 推荐流程

```
1. 查回填清单 → 确定每类的槽数（1 槽 / 4 槽）
2. 统计长度比 → 分「重排」与「重译」两路
3. 占位符单独一批（保留原值）
4. 模板化族先做（券类/装饰品/努力之證…）
5. 归一化模板匹配兜底（吃掉「同文不同断行」）
6. 剩余逐条重译，150 条/批
7. 每批：预检映射 → 校验 → 不过则退回
8. 收尾：全量复检 + 质量报告
```
