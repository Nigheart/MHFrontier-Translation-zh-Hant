## 2. 核查方法

1. 以 `条目ID` 为键，把 `精翻名称` / `精翻说明` 与所属 `日文系列`、`中文名` 对齐。
2. **A 类（归属）**：把说明里出现的怪物名做全量统计，按「日文系列」交叉制表，凡说明提到的怪 ≠ 该系列怪即命中；再逐条看上下文判断是「说明错」还是「标签错」。
3. **B 类（残留）**：正则扫 `[A-Za-z]{2,}`，人工排除合法的等级词（`SP/FX/GX/GF/ZF/ZY/ZX/ZD/PD/HC/HS/LV`）。
4. **C 类（字形）**：对全部字段做 `cp932` 逐字编码测试，得到「不可编码字」集合；再对同义异形字（巖/岩、霸/覇、黒/黑、焰/焔…）做使用频次统计。
5. **D/E 类**：用「`≪≫`／`【】` 是否配对」「`C0x` 是否缺前导 `~`」「行首是否为残片」「句尾是否有终止标点」「是否有 4 字以上重复片段」四组规则筛，人工复核。
6. 建议值统一做三重校验：① `cp932` 可编码；② ` / ` 段数与当前值一致；③ 控制标记数量不增不减（标记本身已残缺的条目在 `依据` 列注明「修復」）。

### 3.2 名称与说明的怪物归属矛盾（A 类）—— 最严重，但**方向与预期相反**

先看日文系列的交叉统计（说明里出现的怪名 → 行数）：

```
ミヅハ     霞龍:24                                    （说明里没有一条提到炎妃龍）
エンプレス  炎王龍:131（来自名称）  炎妃龍:57（来自说明）
カイザー   炎王龍:130             霞龍:18（误插）
サベージ   冰獰龍:30  獰龍:30                          （说明与名称一致，只有标签是「冰狐龍」）
```

**结论 1：ミヅハ 是霞龍，不是炎妃龍。**
- 60 条里凡提到怪名的全部写「霞龍／霞龍素材／幻之霞龍」；
- 造型描述「模倣古代煉金術師裝束」「【烏帽子】道服」＝オオナズチ(霞龍) 的煉金術師系列；
- 炎妃龍在表內另有兩套：`ナナ`（炎妃龍咆哮 等 35 条）与 `エンプレス`。
- 所以：**说明正确，`中文名` 应 `炎妃龍 → 霞龍`（60 行）**。这正是用户提示的「不要想当然改」的情形——照说明改名称，而不是照标签改说明。

**结论 2：エンプレス 是炎妃龍，不是炎王龍。**
- 说明写「采用炎妃龍素材」「宿有焔之**女王**靈魂」；对照 `カイザー` 写「宿有**紅蓮之王**靈魂」——王／妃成对；
- 名称层用「**后**冠／后面罩」（女帝），却冠以「炎王龍・」，本身自相矛盾；
- 青炎（青色的火）是炎妃龍的特徵，紅蓮是炎王龍。
- 所以：**说明正确，`中文名` 应 `炎王龍 → 炎妃龍`（131 行），`精翻名称` 前缀 `炎王龍・ → 炎妃龍・`（130 行）**。

**结论 3：サベージ 的说明与名称都写「冰獰龍」，只有系列标签写「冰狐龍」。**
- サベージ(savage)↔獰龍 语义相合，且 31 行名称／30 行说明一致；
- 但「冰狐龍」若对应 デュラガウア（氷狐竜）则为另一只怪。
- 判定：**倾向 `中文名 → 冰獰龍`**，但**缺日文原文，列为「待确认」**（见 §6）。

**结论 4：真·说明写错怪的，是 `カイザー` 的 18 行。**
```
身体防具:9695 大量使用炎王素材 / 。隨處高級霞龍胴防具。 / 隨處施有充滿高級感的裝飾。
```
「高級**霞龍**」应为「高級**感**」——`霞龍` 是误插（且把「感」挤掉）。已给出建议值。

### 3.3 「巖」与「岩」混用（C 类）

**CP932 实测（逐字 encode 验证）**：

| 字 | 码位 | CP932 | 结论 |
|---|---|---|---|
| 巖 | U+5DD6 | **9BDC ✅** | 可用 |
| 岩 | U+5CA9 | 8AE2 ✅ | 可用（普通字，非专用名用字）|

两者都能编码，所以取舍看译名一致性，建议**统一 `大巖龍`**，理由：
1. 名称层已有 186 行用「大巖龍」，说明层却用「大岩龍」（169 行/182 处）、「大嚴龍」（22 行）——三种写法并存；
2. `大岩龍` 会被读成「大」＋「岩龍」，而 **岩龍＝バサルモス（Basarios）是另一只怪**，属实质歧义；
3. 日文原字为「巌/巖」而非「岩」。

已并入清单一律 `大岩龍 / 大嚴龍 → 大巖龍`。表内另有合法的「岩石」「紅溶岩」（30 行）**不动**。

### 3.4 说明中的机翻生硬（D 类）—— 病因诊断

用户举的三个例子都成立，但它们不是孤立的「译得不好」，而是**同一种结构性损坏**：

```
① 使用貝魯丘洛斯素材備。其表面至今仍帶電。
   实际数据： 使用貝魯丘洛斯素材 / 備。 / 其表面至今仍帶電。
   → 第 2 段只剩「備。」，前一段被切断；不是漏字，是切行时把「制成的腕部裝備」切没了

② 繼承最強種族力量的珠尊貴頭部裝備。
   实际数据： 繼承最強種族力量的珠 / 尊貴胴用裝備。 / ~C07SP防具：赤~C00
   → 「珠」是无义插入字（句法不成立），已删

③ 頭防具。出現兩次（ガスラ、ディアース、アセルス 等）
   → 相邻条目/相邻句子的碎片被拼进同一条
```

**机理（重要）**：装备说明在 `mhfdat.bin` 里是「共享字符串池 + 每条约 4 个指针槽」的结构，每条说明的 3 行分别是池里紧邻的 3 段。回填补丁按「日文字节长度」硬切写入后：
- 中文比日文长 → 本条尾部被下一段的开头覆盖 → **句尾被切断**（1250 行）；
- 中文比日文短 → 本段结尾残留上一段尾巴 → **行首出现 `≫`、`~C00`、「金色的軍隊」等别人的碎片**（31 行）；
- 跨条目的文本错配 → **躯干条目里写「頭裝備」、舞雷龍武器写「桃毛獸素材」、尾晶蠍写「蠻龍素材」**。

已从 `回填定位_请保留.jsonl.gz` 的 `raw_hex`（cp932 原始字节）直接验证：这些错乱**在游戏数据里就已经存在**，不是导出工具的问题。
例：`头部防具:13113` 三槽原字节 = `≫~C00可見怒貌龍` / `兩面性，時而激昂時而` / `寬容。~C28≪辿異防具≫~`。

因此结论是：
> **D 类不能只靠逐条改文本解决。** 必须在回填时重建整个 description 池并重算 4 槽指针（或改为按日文原槽长重排并允许等长扩容），否则改好的文本会被再次切断。
